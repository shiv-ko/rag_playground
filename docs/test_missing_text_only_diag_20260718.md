## ③ 原因パターン別グルーピング

### A（検索ミス）のパターン

1. **文書内の明示的クロスリファレンス先が未検索**（Q62: 「詳細はleaderboard.csvに記載」、Q57: 回帰係数の実値チャンク）
2. **同一ファイル内の他チャンクが検索漏れ（chunk-level miss）**（Q36: slide_7、Q84: slide_6）— ファイル自体は当たっているのに、必要なスライド/チャンクだけ落ちている
3. **一次データファイル（train.csv/xlsx）がそもそも検索対象に上がらない**（Q91: 顧客データ相関、Q57: 抽出シート全件）
4. **全案件横断の集計が必要な質問を単発top-k検索で解こうとしている**（Q24: 欠損行数の案件間比較）
5. **パース時点でチャンクが0件になっている（暗号化ファイルの復号フォールバック漏れ）**（Q79: KAEDEスケジュール.xlsxがencrypted_file_queueにすら未登録）
6. **質問文の語彙とコーパス内表現のズレ（表記ゆれ）**（Q46: 「着手金」がコーパスに文字列として存在せず、実際は`advance_payment_amount`という派生値としてのみ存在）
7. **類似ファイル（近い日付の会議録等）の中から誤ったものが選ばれる**（Q49: 09-08ではなく08-18が正解）

### B（パース欠落）のパターン

- **Wordドキュメント（.docx）の表（テーブル）が一切パースされていない**（Q99が確定例）。`src/parsers/office_parser.py`を確認したところ、`_parse_docx`は`doc.paragraphs`のみを`"\n".join`しており、`doc.tables`を全く参照していない。一方`_parse_pptx`は`shape.has_table`を検知して表セルをテキスト化するロジックを既に持っている（非対称な実装漏れ）。
  - 影響範囲を確認したところ、コーパス中の`.docx`46件中35件（76%）が中身のある表を含んでおり、契約書・会議録・報告資料・**社内用語集.docx**（略語辞典、9表820セル）が軒並み該当する。特に社内用語集.docx実質インデックス内容はわずか134文字（目次見出しのみ）であり、FM/IM/MM/M01-M03/TX/TM/EXT等の略語定義が丸ごと検索不能になっている。これは今回の24問だけでなく、他の略語系質問（RATE, ES等）全般に波及している可能性が高い。
