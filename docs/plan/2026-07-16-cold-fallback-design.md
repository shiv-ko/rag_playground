# cold index時間予算フォールバック設計

embeddingは途中で安全に中断しにくいため、encode開始前に判定する。パース後のユニーク文書hash数とcacheヒット数から未処理数を求め、同一環境の実測throughputで時間を見積もる。

- 全体上限: 10,800秒
- generation・出力予約: 900秒（warm N=3実測445.5秒の約2倍）
- index安全上限: 7,200秒（2時間目標）
- 見積もりが7,200秒を超える、または実測throughputが無い場合: BM25単体へ退避

`--no-cache`改善後のcold N=3を先に再実測する。目標2時間以内で安定すれば実装は保留し、超過または環境差が大きい場合のみTDDで実装する。退避時は未処理数、推定秒、理由をログに残す。

embedding cacheは生データから機械生成する中間表現であり再利用可能と読める。ただし検収では新規データが追加されるため、事前cacheだけに依存せず未登録チャンクの機械処理と退避経路を保つ。
