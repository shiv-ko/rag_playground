## 実施した修正（コミット順）

1. **Phase1是正** `8496508`: flip分析（Q3/Q10/Q14/Q20）に基づき、引用チェックを空白正規化に緩和、
   `looks_like_missing`を「全文がMissing相当の場合のみ」に変更（部分回答の誤ゲート解消）。SYSTEM_PROMPT誤字修正。
2. **ルーティング是正** `e324a3e`: office_style/spreadsheet_stateのelif排他を、質問中のファイル種別ヒントで
   優先順を決めるフォールスルーに変更。
3. **scheduleマッチング是正** `304a896`: 実データは列名「フェーズ」・値「3. 探索的分析・仮説整理」・担当者「A / B」。
   固定キー完全一致では0件だったため、列名部分一致＋番号接頭辞除去＋区切り分割＋ヘッダ残骸除外に変更。
   → valid Q20がT09〜T12を決定的に取得。
4. **calc安全化** `71470d2`: 「の中で」「該当する」をタグ語彙から除去、groupby/argmax系はLLMを呼ばずゲート、
   not_applicableエスケープ追加、ゲート時は通常パスへフォールバック、別案件train.csv使用禁止（NFC比較）。
5. **列挙ゲート実質化** `03fabb4`: `is_enumeration_complete(len(contexts), len(contexts),...)`が常にTrueの
   デッドコードだったのを、実際の候補プール件数を渡す形に配線。
6. **【最重要】NFDパスバグ** `b365e66`: dispatcherの`"プロジェクト" in rel_parts`がNFCリテラル比較のため、
   macOS実データで**全ドキュメントのprojectメタデータがNone**→案件スコープ検索・案件検出・構造化ルーティングが
   実データ上で一度も機能していなかった。rel_partsのNFC正規化で修正。初回phase2_valid(0.03)はこのバグ下の数値。
7. **office_style改善** `（2コミット）`: docxの`highlight_color`（"YELLOW (7)"形式）対応、質問ヒント
   （docx/pptx・ファイル名・P7等ページ番号）による絞り込み、コンテキストの自己記述化
   （「<ファイル> 内の装飾箇所（黄色のハイライト）: <テキスト>」）。
8. **temperature=0は不可**: claude-sonnet-5は`temperature`指定でAPI 400（deprecated）。コミットはrevert済み。
   baselineテストの`"temperature" not in kwargs`はこの制約の固定だった（教訓: 既存アサーションの意図を先に確認する）。

## 学んだこと

- **run間ゆらぎが大きい**（同一コードで0.13〜0.22）。同一回答文でjudgeラベルが反転する例も確認。
  temperatureで固定できないため、今後の実験比較は複数run平均かフリップ分析で行う。
- NFC/NFD問題はretriever（8ceb314）だけでなく、パス文字列を扱う全箇所に波及する。文字列比較の境界では常にNFC正規化。
- 「テストが通る」と「実データで動く」は別物。構造化パスはユニットテスト全PASSのまま実データで全問空振りしていた。
  実データスモーク（少数件の件数確認）を各レイヤーに入れるべき。

   ファイル名だけでなく資料の種類・日付からの推定が必要（Q0/Q23/Q25）。
2. spreadsheet_state: フィルタ条件は可視行/非表示行の値差分の実装が必要（Q11）。Pivot質問はtrain_xlsx系
   artifactsの接続強化（Q6/Q21）。
3. spreadsheet_calc: groupby/argmax対応のCalcSpec拡張（Q7/Q26、現在は安全側Missing）。
4. 通常パス: notebookチャンク分割で条件が泣き別れ→部分コードから誤断定（Q28、唯一のIncorrect）。
