## 学び

- **PyTorchのMPS(Apple Metal)バックエンドはスレッドセーフでない**。`sentence-transformers`のような
  ラッパーを既存の並行パイプライン（`ThreadPoolExecutor`/`asyncio.run_in_executor`経由の複数スレッド）
  に組み込む際は、モデルロード・推論呼び出し全体を`threading.Lock`で直列化する必要がある。単体テストが
  フェイクモデルしか使わない場合、この種のスレッド競合バグはTask8のような実データ・実モデル検証まで
  一切表面化しない——ユニットテストのカバレッジと実運用検証は別物であることを再確認。
- **`command | tail -N`のパイプはコマンドの真の終了コードを隠す**。bashのデフォルトでは最後のコマンド
  （`tail`）の終了コードだけが伝播するため、パイプ元（python）がセグフォルトしても`| tail`経由の
  background実行は「exit code 0」と報告されうる。実行結果の真偽を疑うときは、パイプを外すかリダイレクト
  ＋`echo $?`で直接終了コードを取る。
- **ライブラリのデフォルト値とCLIのデフォルト値は別物として設計すべき**。`Pipeline.__init__`の
  デフォルトを本番用途に合わせてTrueにすると、テストコード側の「デフォルト＝軽量・ネットワーク不要」
  という暗黙の前提が壊れる。CLIスクリプトのargparseデフォルトだけを変えることで、ライブラリのテスト
  容易性と本番の使いやすさを両立できた。
- **検索成功が必ずしもスコア改善に直結しない**（Q6）。CRAGスコアリングはMissing=0・Incorrect=-1なので、
  「検索できなかった問題がMissingのまま」より「検索はできたが回答が不完全でIncorrect」の方がスコアが
  悪化する。ハイブリッド検索の正味の効果は総合スコア（official mean 0.60→0.73）で判断すべきで、
  個別問題の遷移（Missing→Incorrect）だけを見て後退と誤診しないよう注意。
