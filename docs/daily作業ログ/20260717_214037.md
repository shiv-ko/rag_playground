# 20260717_214037 多数決正規化のUnicodeダッシュ統一（Q8偽Missing対策）

## 目的

再現性検証（`20260717_213419.md`）で発見した、`normalize_answer`がU+2212等のダッシュ変種を
別文字扱いして実質同一回答がクラスタ割れする問題（7/16バッチQ8で`no_majority`→Missingの実害）を
1実験1変更で修正する。

## 結果サマリ

- `78f1bde`: ダッシュ/マイナス8種（U+2010〜U+2015・U+2212・U+FF0D）をASCIIハイフンへ畳む変換を
  `normalize_answer`に追加（TDD、683 tests pass）。カタカナ長音「ー」U+30FCと波ダッシュは対象外。
- 反実仮想評価（API不要、保存済みN=3バッチ2つのrun_answersを再多数決）:
  - 7/16バッチ（`predictions_stability_1784198585`）: **Q8のみ** `no_majority`→`majority`
    （偽Missing→「約14,744ドル…」）。他99問は完全無変化。
  - 7/17バッチ（`_1784291565`）: 全問無変化。
- sonnet step-review: CONFIRMEDなし。PLAUSIBLE 2件は対応不要と判断
  （U+2015の理論的過統合リスクは既存の句読点除去と同種で新規リスクでない、
  テスト内の実データ由来文字列は汎用正規化関数の単体テストでルール違反に非該当）。

## やったこと

- RED: ダッシュ変種の同一視・長音非統合・多数決成立の3テストを先に書き失敗を確認。
- GREEN: `_DASH_TRANS`を`_REMOVE_TRANS`適用後に挿入。NFC/casefoldはこの8文字を変えないため
  適用順の相互作用なし（レビューで確認済み）。
- 利用箇所の確認: `normalize_answer`/`stabilize_answers`の利用は提出経路`make_predictions.py`のみ。

## 学び

- 多数決の正規化漏れは「揺れ自体」ではなく「揺れの救済失敗」として現れる（回答は出ているのに
  提出はMissing）。stability JSONのcluster_sizesを見ると1文字差クラスタ割れを機械的に発見できる。
