# 20260716_194413 3時間制限のcold/warm/N=3実測

## 目的

hybrid検索ONのtest 100問について、cold・warm・標準N=3のE2E時間を測り、3時間制限への適合を判定する。

## 結果サマリ

- **cold: 不適合**。parse 14秒、embedding index 3時間32分49秒。generation開始前に3時間を超えたため中止。停止までのwall 12,825.41秒。
- **warm単発: 適合**。index 66秒、generation 120.5秒、E2E 189.47秒（3分9.47秒）。
- **warm標準N=3: 適合**。index 65秒、3run＋多数決＋出力を含むE2E 445.50秒（7分25.50秒）。
- warm N=3は2時間目標を大幅に満たすが、未知データでembedding cacheが無効になるcold実行は上限超過する。

## やったこと

- cold: `run_pipeline.py --no-cache --no-judge`を`/usr/bin/time -p`で実測。index完了時点で上限超過のためAPI生成を停止。
- warm: `benchmark_warm_test_1784198120.json`を保存。100件、generator elapsed 120.5秒、input 327,824 / output 31,066 tokens。
- N=3: `/private/tmp/benchmark_predictions.csv`へ出力し、100行・ID 0〜99・欠落run 0を確認。監査は`predictions_stability_1784198585.json`。
- N=3多数決内訳: unanimous 29、majority 5、all_missing 60、no_majority 6。最終回答あり34問。
- 条件: macOS 26.5.2 arm64、hybrid ON、`cl-nagoya/ruri-base`、`claude-sonnet-5`、top-k 5、concurrent 5、threshold 0.4。

## 学び

- coldの支配項はparseではなく102,263チャンクの埋め込み生成であり、parse最適化では解決しない。
- 永続embedding cacheがあればindexは約65秒まで短縮され、標準N=3でも8分未満。
- 新規データ検収では既存cacheをそのまま使えない可能性があるため、warm結果だけで3時間適合とは判断できない。

## 残課題

- 再現性検証より先に、cold埋め込み構築のバッチサイズ・デバイス・対象チャンク削減・キャッシュ再利用単位を診断する。
- 改善後、cold indexとcold N=3を再実測して3時間以内、目標2時間以内を確認する。
