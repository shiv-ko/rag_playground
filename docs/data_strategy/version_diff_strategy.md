# 新旧比較戦略

## 1. なぜ専用化が必要か

新旧比較設問は、ファイル名規則が統一されていない。通常検索で旧版と新版の両方が偶然ヒットすることを期待すると、取りこぼしや混入が起きる。

観測された版パターン:

- `提案書old.pptx` -> `提案書.pptx`
- `old/提案書.pptx` -> `提案書.pptx`
- `提案書_v1.pptx` -> `提案書_v2.pptx` -> `提案書_v3.pptx`
- `提案書_v1.pptx` -> `提案書_final.pptx`
- `最終報告_old.pptx` -> `最終報告.pptx`
- `old/最終報告.pptx` -> `最終報告.pptx`
- `01_eda_old.ipynb` -> `01_eda.ipynb`
- `スケジュール_r1.xlsx` -> `スケジュール_r2.xlsx`

## 2. version_pairsの作り方

全ファイルに以下を付与して、同一案件・同一資料種別内でペア候補を作る。

- `project_name`
- `section`
- `document_type`
- `normalized_title`
- `version_tag`
- `version_order`

版順序:

`old` < `draft` < `r1` < `v1` < `r2` < `v2` < `v3` < `final` < 無印最新版候補

無印が最新版とは限らないが、このデータでは `old/無印` や `old.pptx/無印` のパターンがあるため、同一タイトルの無印は新版候補にする。

## 3. 差分抽出の粒度

形式ごとに差分単位を変える。

| 形式 | 差分単位 |
|---|---|
| pptx | スライド番号、テキストボックス、表、図形、色/強調 |
| docx | 見出し、段落、表セル、書式 |
| xlsx | sheet、行、セル、値、数式、色、ステータス |
| ipynb | markdownセル、codeセル、outputs、図表 |
| pdf | ページ、テキストブロック、画像領域 |

質問で「案件遂行に関連する実質的な変更」とある場合、単純な文字差分をそのまま出すとノイズが多い。差分後に、担当者、金額、期間、スコープ、タスク、モデル、KPI、ステータスなどの業務的変更だけを抽出する。

## 4. 差分の分類

差分は以下に分類する。

- `scope_change`: 対象/対象外、作業範囲。
- `schedule_change`: 週、日付、タスク、マイルストーン。
- `role_change`: 担当者、レビューア、責任者。
- `cost_change`: 金額、単価、工数、請求。
- `model_change`: モデル、特徴量、評価指標。
- `status_change`: 未着手/進行中/完了など。
- `wording_only`: 表記修正だけ。
- `format_only`: 書式だけ。

設問が「案件遂行に関連する」と指定する場合、`wording_only` と `format_only` は原則除外する。

## 5. 回答ゲート

差分設問で答える条件:

- 旧版/新版のペアが一意に決まる。
- 両ファイルを同じ抽出器で構造化できている。
- 差分が業務カテゴリに分類されている。
- 列挙対象の差分数が確定している。

差分が一部しか取れない場合はMissing。比較問題は部分一致がIncorrectになりやすい。
