# metadataとルーティング戦略

## 1. なぜmetadataが勝ち筋か

このデータセットでは、質問文が正式ファイル名や正式社名で書かれるとは限らない。略称、社内用語、資料種別、会議ID、ページ、シート名、図表名が検索キーになる。本文だけをBM25に入れると、正しいファイルに到達できない。

例:

- `KSSのfigure_06.png`
- `AYMのMM`
- `MINAMINOのPL`
- `東都のCT`
- `京ソのPP_final.pptx`
- `社内管理のAPR`
- `IMにあるFM`

## 2. 全ユニット共通metadata

すべての抽出単位に以下を付ける。

| key | 内容 |
|---|---|
| `source_path` | `共有ドライブ` からの相対パス |
| `project_name` | 案件フォルダ名。社内管理はnull |
| `project_aliases` | 主略称、短縮名、質問で使われうる別名 |
| `section` | `00.提案` から `06.報告書`、または `社内管理` |
| `document_type` | `PP`, `CT`, `PLAN`, `MM`, `FR`, `APR`, `FM` など |
| `file_name` | 拡張子付きファイル名 |
| `stem` | 拡張子なしファイル名 |
| `extension` | `.docx`, `.pptx`, `.xlsx` など |
| `version_tag` | `old`, `v1`, `v2`, `v3`, `final`, `draft`, null |
| `unit_type` | `paragraph`, `table`, `slide`, `page`, `sheet`, `cell`, `image`, `code_cell` |
| `unit_id` | ページ番号、スライド番号、シート名、セル番地など |
| `date` | ファイル名や本文から取れる会議日/契約日 |
| `ids` | `M01`, `A10`, `MS3`, `T12` などID候補 |

## 3. 案件レジストリ

`プロジェクト/` 配下の10案件を実行時に列挙し、社内用語集・契約書・提案書から別名を補完する。

保持する項目:

- 正式案件名
- 主略称
- 質問で出る短縮名
- 業界カテゴリ
- 顧客担当者
- DA側担当者と役割
- 契約方式: fixed / time_and_materials 等
- 契約期間
- 見込金額、確定金額、着手金、税率
- 開始日、終了日、支払月

案件名のハードコードは避けるが、データから導出したレジストリを中間成果物として保持するのは汎用的な処理。

## 4. 社内用語レジストリ

社内用語集から、略語をクエリ展開と資料種別解決に使う。

特に重要:

- `PP`: 提案書
- `CT`: 契約書
- `PLAN` / `PL`: 計画、スケジュール
- `MM`: 会議資料/議事録系
- `FR`: 最終報告
- `APR`: 決裁基準
- `FM`: 座席表
- `TG`: 目的変数
- `ES`: エンジニア/担当者系の役割
- `EXT`: 内線番号
- `ESTH`: 見込工数
- `ACTH`: 実績工数
- `RATE`: 単価

用語は単に全文検索へ足すだけでなく、ルーティングに使う。例えば `PL` が出たら `02.計画` とスケジュール系xlsxを優先する。

## 5. ルーティング規則

質問解析で、候補データソースを先に絞る。

| 質問の手掛かり | 優先ソース |
|---|---|
| `PP`, 提案書 | `00.提案` |
| `CT`, 契約書, 契約条件 | `01.契約` |
| `PLAN`, `PL`, スケジュール, WBS | `02.計画` |
| `train.csv`, `train.xlsx`, Sheet, Pivot | `03.データ` |
| `metrics.json`, Notebook, modeling.py, figure | `04.分析` |
| `MM`, 会議ID, アクションID, 中間報告 | `05.会議` |
| `FR`, 最終報告 | `06.報告書` |
| `APR`, 決裁, 座席, EXT | `社内管理` |

ルーティング結果は検索フィルタとして使うが、根拠が弱い場合は全体検索も併用する。略称解決に失敗した場合でも、ファイル名・資料種別・日付で再検索できるようにする。
