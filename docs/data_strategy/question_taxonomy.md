# 設問分類と得点戦略

## 1. 観測された設問タイプ

valid 30問とtest 100問を読むと、設問は複数能力の組み合わせになっている。キーワードベースの概算では、test側で特に多いのはExcel状態、社内略語、Office書式、計算/集計、新旧比較。

| タイプ | valid概算 | test概算 | 得点上の意味 |
|---|---:|---:|---|
| Excel状態 | 3 | 23 | 最優先。セル色、フィルター、Pivot、シート表示を読めないと落とす問題が多い |
| 社内略語・参照資料 | 7 | 19 | ルーティングと資料種別解決の土台。全タイプに効く |
| 書式・視覚属性 | 2 | 18 | 部分一致が危険な抽出問題が多い。専用抽出と高いゲートが必要 |
| 計算・集計 | 7 | 16 | LLM生成よりコード計算で確実に取るべき |
| 新旧比較 | 1 | 9 | ファイルペア同定と差分抽出を自動化すればまとまって伸びる |
| 画像・グラフ | 2 | 5 | 件数は中程度だが、数値完全一致が必要で誤答リスクが高い |
| コード・Notebook | 3 | 3 | 件数は少ないが、構造化すれば確度高く取れる |
| 複数案件横断 | 2 | 3 | レジストリ化できれば高精度。手作業的RAGでは危険 |

## 2. 攻める順番

1. **Excel状態 + 集計**
   - testでの出現が多い。
   - `openpyxl` 等で機械的に抽出でき、LLM依存を下げられる。
   - セル色・数式・シート・フィルターが取れれば、多くの難問が一気に射程に入る。

2. **Office書式 + ページ/スライド**
   - 太字、下線、イタリック、赤字、黄色ハイライト、コメント、ページ番号が問われる。
   - 通常のテキスト抽出では消える情報なので、先に専用抽出を作る価値が高い。

3. **metadata/略称ルーティング**
   - `KSS`、`AYM`、`MINAMINO`、`PP`、`PL`、`FR`、`CT`、`MM` などを解決できないと検索対象を絞れない。
   - これは全設問タイプのリコールを上げる横断投資。

4. **新旧比較**
   - 旧版の置き方が統一されていないため、普通の検索では見落としやすい。
   - 比較問題は列挙型になりやすく、全要素を取れない場合はMissingが安全。

5. **analysis成果物統合**
   - `metrics.json`、`leaderboard.csv`、Notebook、`modeling.py`、図表をつなぐ。
   - 設問は「最良モデル」「実行時に適用される値」「図の目盛り」など、単一ファイルでは完結しないことがある。

## 3. 守るべき問題

次は能力がない状態で回答するとIncorrectになりやすい。

- 「すべて抜き出してください」
- 「変更点を挙げてください」
- 「太字、下線、イタリックのすべて」
- 「ハイライトされているセル/行」
- 「グラフのy値を小数第N位」
- 「全案件で」「完了案件のうち」

これらは、対応する専用抽出結果が空または不完全ならMissingを返す。特に列挙問題は部分一致がIncorrect扱いになりうるため、検索ヒットだけで答えない。

## 4. 評価のための分類ラベル

valid/testの各質問に、少なくとも以下のラベルを付ける。

- `single_text`
- `office_style`
- `spreadsheet_state`
- `spreadsheet_calc`
- `image_graph`
- `code_static`
- `notebook_output`
- `analysis_metrics`
- `version_diff`
- `cross_project`
- `contract_rule`
- `internal_terms`
- `list_extraction`
- `numeric_exact`

このラベルで、実験ごとの改善/悪化を能力別に見る。全体スコアだけを見ると、どのデータ戦略が効いたか判断できない。
