# 全案件横断・社内管理・契約ルール戦略

## 1. 対象データ

横断問題は、単一文書の検索ではなく、複数案件の構造化テーブルを作ってから解く。

主なソース:

- `社内管理/社内用語集.docx`
- `社内管理/データアステル社内管理_決裁基準.md`
- `社内管理/データアステル社内規定_パスワード導出規則.docx`
- `社内管理/座席表.pptx`
- 各案件の `01.契約/契約書*.docx`
- 各案件の `00.提案`
- 各案件の `02.計画/スケジュール*.xlsx`
- 各案件の `06.報告書`
- 各案件の `03.データ`

## 2. 横断レジストリ

案件ごとに以下を正規化して保持する。

| テーブル | 主な項目 |
|---|---|
| `projects` | 正式名、主略称、別名、業界、完了状態 |
| `contracts` | 契約方式、契約期間、税込金額、税抜金額、着手金、単価、見込工数、実績工数 |
| `payments` | 支払月、精算額、確定額、差額 |
| `people_assignments` | 人名、役割、案件、資料種別、タスクID |
| `schedule_tasks` | タスクID、フェーズ、担当、期間、工数、ステータス |
| `action_items` | 会議ID、アクションID、担当、状態、期限 |
| `data_profiles` | 行数、欠損数、目的変数、サンプル数 |
| `approval_rules` | APRレベル、金額条件、医療案件補正、契約方式補正 |

## 3. 社内管理の使い方

社内管理は検索対象ではなく、ルールと辞書として使う。

- 社内用語集: クエリ展開、資料種別解決、案件略称解決。
- 決裁基準: APR-M1/M2/M3判定、医療案件補正、time_and_materials補正。
- パスワード規則: 保護ファイル復号。
- 座席表: 内線番号、左右/向かいなど位置関係。

## 4. 契約・請求計算

計算問題は多い。契約書・提案書・最終報告から、金額と工数の意味を正規化する。

重要項目:

- 見込金額（税込/税抜）
- 確定金額（税込/税抜）
- 着手金
- RATE
- ESTH
- ACTH
- 固定金額契約か事後精算か
- 税率
- 契約期間
- 支払月

例:

- 実績工数が見込工数の4分の3だった場合の減額。
- ACTHが指定値だった場合の税込請求額。
- RATE変更日。
- 1行あたり契約金額。
- 支払月ごとの精算総額。

LLMではなく、構造化値と計算式で答える。金額はカンマ、円、税込/税抜の扱いを最後に整形する。

## 5. 人員・座席・内線

人名は複数資料に出る。

- 提案書: 実施体制。
- 契約書: 甲乙担当者。
- 計画: タスク担当者。
- 会議録: 出席者、アクション担当。
- 座席表: 内線、位置関係。

勝つためには `people_registry` を作る。

項目:

- 人名
- 所属/顧客/DA側
- 役割
- 案件
- タスクID
- アクションID
- 内線番号
- 座席位置

「もっとも多くの案件にかかわっている人」「右側に座っている人」「着手金が最も高い案件のESの内線番号」は、このレジストリ同士の結合で解く。

## 6. 回答ゲート

横断問題で答える条件:

- 対象案件集合が確定している。
- 各案件で必要項目が抽出済み。
- 社内ルールの適用順序が明確。
- 集計対象の欠損がない。
- 計算式と丸め規則がログに残る。

1案件でも必要項目が欠ける「すべて挙げる」問題はMissingを優先する。
