# Office・PDF・視覚書式戦略

## 1. 対象データ

主な対象は以下。

- `00.提案`: pptx/pdf/docx。提案書、調査資料、旧版。
- `01.契約`: docx。契約書、一部パスワード保護。
- `05.会議`: docx/pdf/pptx。会議録、報告資料、基礎分析。
- `06.報告書`: pptx/pdf。最終報告、旧版。
- `社内管理`: docx/pptx/md。用語集、パスワード規則、座席表、決裁基準。

## 2. 勝ちに必要な抽出情報

本文だけでなく、次を構造化する。

| 形式 | 必須情報 |
|---|---|
| docx | 段落、表、見出し、太字、下線、イタリック、文字色、ハイライト、コメント、ページ推定 |
| pptx | スライド番号、テキストボックス、表、図形内テキスト、塗り、文字色、強調、ノート、画像 |
| pdf | ページ番号、本文、表、画像領域、OCR結果、レイアウト位置 |

質問例:

- 太字で記載されている箇所を抽出。
- 太字、下線、イタリックのすべてに該当する箇所を抽出。
- 黄色ハイライトかつ赤字の部分を抜き出す。
- 報告資料の見出しがあるページを答える。
- 提案書P7で赤で強調されている箇所を抜き出す。

## 3. 抽出単位

Office/PDFは、ファイル単位ではなく以下の単位で保持する。

- `page`: PDFページ、推定ページ。
- `slide`: pptxスライド。
- `paragraph`: docx段落、PDFテキストブロック。
- `table`: 表とセル。
- `run`: docxの同一書式範囲。
- `shape`: pptxのテキストボックス/図形。
- `image`: 埋め込み画像。

書式質問では `run` / `shape` 単位の抽出が必要。段落単位に潰すと、どの文字列だけが強調されているかを失う。

## 4. 重要なmetadata

- `page_number`
- `slide_number`
- `paragraph_index`
- `table_index`
- `cell_address` または `row/col`
- `text`
- `bold`
- `italic`
- `underline`
- `font_color`
- `highlight_color`
- `fill_color`
- `comment_text`
- `bbox` PDF/OCR用

色は生RGBに加えて、`yellow`, `red`, `blue`, `orange` などに正規化する。質問は自然言語の色名で来るため、RGBそのままだと照合しにくい。

## 5. PDF戦略

PDFはテキストPDFと画像PDFで処理を分ける。

1. テキスト抽出できるページは、本文と座標を取得する。
2. テキスト抽出が薄いページは、ページ画像としてOCR/VLMに渡す。
3. ページ番号を必ず保持する。
4. 表やグラフがあるページは、画像としても保存してVLM参照可能にする。

ページ番号を問う設問があるため、チャンク化でページ境界を壊さない。

## 6. 回答ゲート

次の条件を満たすときだけ抽出型設問に答える。

- 質問で指定された案件・資料種別・版が一意に解決できている。
- 書式条件を満たす抽出単位が機械的に列挙できている。
- `すべて` 型の設問では、対象ファイル全体を走査済み。
- ページ番号回答では、ページ境界が信頼できる。

条件を満たさない場合はMissing。書式抽出の部分一致はIncorrectのリスクが高い。
