## ③ 汎用修正候補と期待改善問数の見積もり

いずれも特定の質問ID・特定ファイル名への分岐ではなく、構造的な仕様・列名・パターンへの一般的対応。

1. **CalcSpec文法の拡張（グループ相対比較・比率集計・標準化列の一般サポート）** — パターンA対応
   - 内容: `SpreadsheetCalcAnswerer`のJSON仕様に、(i) 「サブグループの集計値を動的閾値として使う2段階フィルタ」、(ii) count/countの比率(percentage)集計タイプ、(iii) 列の標準化(z-score)変換、のいずれかまたは組み合わせを追加。
   - 期待改善: 直接はQ30の1問。ただし「グループ内平均との比較」「割合(%)」を問う集計質問はtrain.csv系の他の未診断Missing問題にも一定数存在しうるパターンのため、7問超の波及可能性あり（本タスクの母集団=残り50問Missingの再調査は範囲外）。

2. **`_SCHEDULE_MATCH_KEY_PARTS`への"種別"列追加（列名ホワイトリストの拡張）** — パターンB対応
   - 内容: `src/retriever/structured_context.py`の`_schedule_row_matches_question`が参照する列名候補に、既存の「フェーズ/担当/ステータス/成果物」に加えて「種別」（WBS/スケジュール表で頻出する分類列）を追加。特定ファイル名・特定案件への分岐ではなく、スケジュール表という構造化フォーマット共通の列名への対応。
   - 期待改善: 直接Q90の1問。実装コストが最小（1行のタプル拡張）である一方、他案件のスケジュール表でも「種別」列（バッファ以外にも「レビュー」「承認」等の分類）に基づく集計を問う同型の未見問題があれば同時に救済できる可能性が高く、修正コスト対効果は今回の7問の中で最良。

3. **複数文書・複数案件横断の専用extractor新設（実施体制ロスター、ID発行台帳）** — パターンC/E対応
   - 内容: (i) PP/契約書/PLAN/FRから「実施体制」表を構造化するartifact、(ii) 会議録等からM/T/A形式のIDをdocument横断でユニーク集計するID台帳artifact、(iii) `contract_rule`系ハンドラで結果0件時に「該当なし」を最終回答として確定させる（cross_projectと同様の設計に統一）、の3点。
   - 期待改善: 各1問（Q86, Q92, Q38）で計3問だが、(i)(ii)は互いに独立したドメイン固有ロジックであり汎用エンジン1本で同時に救える設計にはなりにくい。**Q79/Q92向け新規集計answererが過去「期待値低」で保留された判断について**: 今回の診断はその判断を追認する結果となった。理由は、(a) 各問が要求する集計対象（人員ロスター表・ID採番ログ・決裁基準の空集合確定）が互いに無関係でコード共有できない、(b) 各ドメインとも網羅性（全10案件×最大4文書、全docx横断）を保証する抽出には相応の実装・検証コストがかかる、(c) 1実装につき救済見込みは概ね1問、という費用対効果の低さが3問すべてで共通して確認された。(iii)（空集合確定ロジックの統一）は最小コストで実装可能だが、Q38の真のground truthが「該当0件」かどうか未確定なため、効果は不確実（中確信）。

4. **スキャンPDFへのOCR/画像読解導入** — パターンD対応
   - 内容: 既存の`image_or_graph`向け`vlm_answerer`と同様のVLM/OCR経路をPDFページ画像にも拡張する（PDFパーサがテキスト抽出0〜数十文字だった場合のフォールバック）。
   - 期待改善: 直接Q64の1問。ただし実測では同種の低抽出PDFがQ64の青潮以外にも広範に存在（白峰4件全て0文字、東都人材プラットフォーム2件0文字、蒼樹会みなみ野4件0文字、東都提案書PDF0文字など、合計10件以上）。これらPDFに依存する他のMissing問題が残り50問中にどれだけあるかは本タスクのスコープ外だが、投資対効果は7問中で最も広範囲に波及する可能性が高い。既存コードコメントで既知の限界として記録済みのため、優先度検討の材料として明記。
